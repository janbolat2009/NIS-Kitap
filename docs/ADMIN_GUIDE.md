# NIS Kitap — руководство для сотрудников и администратора

## Как устроено

- Браузер **только читает** Firestore (свои документы и публичные: классы, фонд, рейтинг шаңыраков, опубликованные отзывы).
- Всё, что требует доверия, — брони и фонд, подтверждение чтения и очки, классы и шаңыраки, награды, отзывы, роли и настройки — выполняет сервер `api/v2` (Vercel, Firebase Admin SDK) в транзакциях.
- Для каждого действия сервер проверяет токен Firebase, **подтверждённый email** и роль. Роль берётся только из `config/access.json` и `roles/{email}`. Действия сотрудников дополнительно проверяют, что токен не отозван.
- Никто не может подтвердить, наградить или скорректировать очки **своего** аккаунта.

## Класс и шаңырак

1. Техадмин загружает соответствие на **/admin/classes**: CSV `academic_year,class_name,shanyrak_name`, сначала «Предпросмотр», потом «Применить». Пустой шаңырак означает, что класс есть в списке, но пока не сопоставлен.
2. Ученик выбирает класс при регистрации или после первого входа. **Шаңырак сервер берёт из таблицы**; прислать свой шаңырак ученик не может. Исправить класс самостоятельно можно один раз за 7 дней, дальше — только через техадмина (с указанием основания).
3. Каждая операция с очками хранит класс и шаңырак **на момент начисления**. При переводе ученика или изменении соответствия прошлые очки остаются в прежнем шаңыраке, новые идут в новый. Все переводы видны в «Ученики → История классов».
4. Новый учебный год: «Скопировать с повышением» (10A → 11A) или «как есть», затем сменить текущий год в настройках.

Черновик соответствия на 2026–2027 — `import-templates/class_map_2026-2027_DRAFT.csv`. Он собран из списков кураторов и лидеров шаңыраков и **требует подтверждения школой**, сам по себе не загружен.

## Очки

- По умолчанию: 100 за подтверждённую книгу, +25 за книгу из «100 кітап», +20 за засчитанный отзыв, достижения за 10/25/50/75/100 книг. Значения меняются на **/admin/settings** и действуют на будущие начисления.
- «Прочитано», отмеченное учеником, очков не даёт. Очки появляются только после подтверждения библиотекарем.
- Журнал `points_ledger`: кто, за что, по какой книге, когда, сколько, кем подтверждено. Одно действие начисляется один раз (детерминированный id + транзакция).
- Ошибочное начисление отменяется **отдельной** записью с противоположным знаком; исходная запись помечается «отменено». Отменить подтверждение целиком — «Ученики → Прочтения → Отменить подтверждение».

## Брони и фонд

Всего = свободно + забронировано + выдано.

1. Ученик бронирует книгу → экземпляр **удерживается** на `holdHours` часов (по умолчанию 48), но не считается выданным.
2. Библиотекарь «Подготовить» → дата, время, место. Можно сразу отправить письмо или отправить позже, а также повторно — вторая бронь при этом не создаётся. Статус письма виден в строке брони.
3. «Выдать» → экземпляр переходит из «забронировано» в «выдано», появляется срок возврата.
4. «Принять возврат» → экземпляр снова свободен.
5. Бронь, которую не забрали, истекает автоматически (cron Vercel раз в сутки и при каждом открытии списка).
6. Число экземпляров меняет **Фонд → Изменить фонд** с основанием. Меньше, чем выдано плюс забронировано, сделать нельзя. Все изменения есть в журнале фонда.

## Письма

Письма уходят **только от SMTP-учётки сервера** (`SMTP_USER`). Другой адрес в `MAIL_FROM` используется, только если `MAIL_FROM_VERIFIED=true`, то есть почтовый сервис подтвердил этот домен или адрес. Проверка подключения: /admin/settings → Почта.

## Переменные окружения (Vercel → Settings → Environment Variables)

| Переменная | Обязательно | Назначение |
|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | да | JSON сервисного аккаунта nis-kitap-2025 (сырой или base64) |
| `FIREBASE_PROJECT_ID` | нет | по умолчанию `nis-kitap-2025` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | для писем | официальный почтовый ящик библиотеки |
| `MAIL_FROM_NAME` | нет | имя отправителя, по умолчанию «Библиотека NIS Kitap» |
| `MAIL_FROM`, `MAIL_FROM_VERIFIED` | нет | другой адрес отправителя, только с подтверждённым доменом |
| `MAIL_REPLY_TO` | нет | адрес для ответов |
| `CRON_SECRET` | рекомендуется | Vercel подставляет его в запрос cron истечения броней |
| `SITE_URL` | нет | ссылка в письмах, по умолчанию https://www.niskitap.site |
| `ALLOWED_ORIGINS` | нет | дополнительные домены для CORS |
| `GEMINI_API_KEY` | для поиска с ИИ | как раньше |

## Обновление с прошлой версии и откат

1. Опубликовать правила и индексы: `npm run rules:deploy`.
2. Выложить сайт (Vercel).
3. Техадмин: **/admin/settings → Обслуживание → «Проверить (без изменений)»**, затем **«Выполнить миграцию»**. Миграция только добавляет поля: старые «active»-брони становятся «Новая заявка» и удерживают экземпляр, если он свободен. Записи журнала очков получают поле `action`, итоги пересчитываются из журнала. Перед изменением каждый документ копируется в `migration_backups`.
4. Откат данных: `POST /api/v2/admin/maintenance/rollback {runId}` (техадмин) восстанавливает копии и удаляет созданные миграцией документы. Откат кода — предыдущий деплой в Vercel и прежние правила (`git checkout <commit> -- firestore.rules && firebase deploy --only firestore:rules`).
